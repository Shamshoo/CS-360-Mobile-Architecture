# CS-360 Inventory App

This repository contains my Project Three Android app for SNHU CS-360 (Option 1: Inventory App). The ZIP file includes the full Android Studio project, with the UI I designed in Project Two and the working code I added in Project Three.

The aim of the app was to enable the warehouse staff to track the inventory on their phone rather than on paper or a desktop computer. The requirements included a screen for logging in that is also used to create an account by a new user, a SQLite database with tables for users and items, a grid presenting every item, the capability to add, delete and alter the quantity of items and an SMS alert when the quantity of an item becomes zero. It meets the requirements of workers who rapidly update the counts during a shift, supervisors who have to be aware of when something runs out and managers who add new items.

To do this, the app has four screens (login, the inventory grid, the Add Item form and an SMS permission screen) and the plus, minus and delete buttons sit right on each row, so a count can be altered in one tap, out-of-stock items turn red so they are more prominent and every screen can be followed back to the grid. The SMS screen also describes why the app is requesting the permission and the app is still operational if the user declines. I believe the design was successful since it fits how the app is actually used, with short visits where a worker just needs to find an item and update it.

I coded the app by initially creating the UI and then coding one feature at a time and testing it before going on. I kept all the database code inside the DatabaseHelper class and the screens simply call addItem and deleteItem; I also used clear names and comments. I will use this approach in future projects as it makes problems easier to find and the code easier to change.

I tested each part in the Android emulator: wrong logins, correct logins, making accounts, adding, updating and deleting items, closing and reopening the app to check that data was kept, and allowing and denying the SMS permission. This is important as an app can compile without errors and still not behave the way a user would expect, and it revealed issues I would not find just by reading the code. Layouts appearing differently in the emulator than in the preview was an example.

One challenge was testing the SMS deny option, as Android requests permission only once, so I had to clear the app storage. While writing the launch plan, I also realised that Google Play restricts SMS permissions, so I decided to rely on regular notifications for the real release. The area where I was most successful was the inventory grid, as it links the database, the user-centered design and the SMS alert into one screen.
